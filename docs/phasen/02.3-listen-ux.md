## Ziel

Einkaufslisten von Minimal-UI zu **schnellem Listen-Arbeiten** (eine Zeile pro Artikel, Inline-Add) und **haushaltsspezifischen Listen** (DM, Handwerk, …). Name-Vorschläge aus Historie.

## Entscheidungen (User-Test 2026-09-15)

| Thema | Entscheidung |
| --- | --- |
| Kategorie-Filter | Chips wie **Tabs** — bleibt; Tab **„Alle“ entfällt** |
| Standard-Tab | Erste Liste beim Öffnen aktiv (nach Migration: Default-Listen) |
| Hinzufügen | Button **unter** den Chips; nur **Textfeld** (Kategorie = aktiver Tab) |
| Anlegen/Abbrechen | **✓** und **✗** rechts im Textfeld (kein großes Formular) |
| Zeilen-Meta | **Kein** „von User“, kein „Erledigt“-Text, **keine** Kategorie in der Zeile |
| Zeile | Checkbox links (styled), Name, Löschen-Icon **rechts nur bei Fokus/Tap** auf Zeile |
| Custom Listen | Pro Haushalt anlegbar (z. B. DM, Handwerk); **Plus oben rechts** in Card → Modal |
| Kategorie bearbeiten | Zwei kleine Buttons **am Ende der Chip-Reihe** (nur aktiver Tab): Bearbeiten / Löschen |
| Kategorie löschen | **Nur Inhaber** (`household.ownerId`); Bestätigung; bei Items: **verschieben nach** andere Liste (wenn machbar) |
| Autocomplete | Ab **3 Zeichen**, **Teilmatch** auf bisherige Artikelnamen des Haushalts (z. B. „Milch“ → „Vollmilch 3,5%“) |
| Enum `ShoppingCategory` | Ersetzt durch **`shopping_lists`** + `listId` auf Items; Default-Listen migrieren |

## CRUD — Custom Listen (`shopping_lists`)

| | Inhaber | Mitglied (nicht Inhaber) |
| --- | --- | --- |
| **C** | ja (Modal Plus) | ja |
| **R** | alle Listen des Haushalts | gleich |
| **U** | Name/Reihenfolge jeder Liste | eigene angelegte? → **alle** (kooperativ, wie Items) |
| **D** | ja; mit Items → Verschieben-Dialog | **nein** |

**D begründet:** Aufräumen falscher Listen; Mitglied darf eigene Items löschen, nicht die gemeinsame Listen-Struktur zerlegen.

**Verschieben beim Löschen:** Inhaber wählt Ziel-Liste; Items werden per Batch-Update umgehängt, dann Liste löschen. Fallback: Löschen blockieren mit klarer Copy, wenn Verschieben zu aufwendig — Ziel ist Verschieben.

## CRUD — Listenpunkt (unverändert inhaltlich)

`listId` statt Enum `category`. Abhaken, `addedBy`, Lösch-Rollen wie [phase-2-crud-roles.md](../design/phase-2-crud-roles.md).
