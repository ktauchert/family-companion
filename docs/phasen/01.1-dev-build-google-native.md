## Warum eigene Phase?

Phase 1 liefert den Produktpfad mit **E-Mail/Passwort in Expo Go**. Google auf Android braucht einen **eigenen Build** (Play Services, SHA-1, `google-services.json`) — kein Expo Go, kein Web-OAuth, kein `auth.expo.io`. Code und Plugin sind vorbereitet; diese Phase ist **Setup + Gerätetest**, kein neues Feature.

## Arbeitspakete

### WP1 — Firebase & Google Cloud einrichten

- [ ] **Android-App in Firebase** (falls noch nicht): Paket `com.familycompanion.app` — steht schon in [`apps/mobile/app.config.ts`](../../apps/mobile/app.config.ts)
- [ ] **`google-services.json`** herunterladen → nach `apps/mobile/google-services.json` *(gitignored, nicht committen)*
- [ ] **SHA-1 (Debug)** ermitteln:
  ```bash
  npm run firebase:sha1
  ```
  Ausgabe `SHA1:` in Firebase → Projekt-Einstellungen → Android-App → Fingerabdruck eintragen. Danach ggf. **neue** `google-services.json` laden.
- [ ] **OAuth-Client „Web“** (Firebase/Google Cloud): Client-ID kopieren — endet auf `.apps.googleusercontent.com`. Das ist **`EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`** (für natives Sign-In als `webClientId`, nicht der Android-Client allein).
- [ ] **OAuth-Client „Android“** mit Paket `com.familycompanion.app` + gleichem SHA-1 — wird oft mit Firebase Android-App mit angelegt; prüfen, dass er existiert.
- [ ] Firebase **Authentication → Google** Provider eingeschaltet (war für Web schon nötig)

### WP2 — Env Mobile

- [ ] `apps/mobile/.env.local` aus [`.env.example`](../../apps/mobile/.env.example) — Werte **ohne** Anführungszeichen
- [ ] `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID=<Web-Client-ID>` gesetzt
- [ ] Alle `EXPO_PUBLIC_FIREBASE_*` wie in der Web-App (dieselbe Firebase-App)
- [ ] **Nicht** bauen: Expo-Go-Web-OAuth, `auth.expo.io`, Redirect-URI für `exp://` ([Lessons](../lessons-learned.md))

### WP3 — Dev-Build erzeugen und installieren

**Option A — lokal (schneller Iterationszyklus, wenn SDK da):**

```bash
cd apps/mobile
npx expo prebuild --platform android   # nur beim ersten Mal oder nach Plugin-Änderung
npx expo run:android                   # baut und startet auf Gerät/Emulator
```

**Option B — EAS (ohne lokales Android SDK):**

```bash
cd apps/mobile
npx eas-cli build --profile development --platform android
# APK/AAB installieren; ggf. eas.json anlegen *(ergänzt in Phase 1.1, falls nötig)*
```

- [ ] Build läuft durch (kein fehlendes `google-services.json`, kein Plugin-Fehler)
- [ ] App startet **nicht** in Expo Go — eigenes Icon / `familycompanion://` Scheme
- [ ] Login-Screen zeigt **„Mit Google anmelden“** (nicht nur den Expo-Go-Hinweis)

Root-Shortcut weiterhin: `npm run dev:mobile` ist **Expo Go** — für Google-Test bewusst **Dev-Build** nutzen.

### WP4 — Google nativ E2E

- [ ] App öffnen → Login → **Mit Google anmelden** → Google-Konto wählen
- [ ] Kein Fehler `Missing EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`, kein `idToken`-Fehler, kein `DEVELOPER_ERROR` (typisch: falscher SHA-1 / falsche Client-ID)
- [ ] Nach Login: Onboarding **oder** Heute/Haushalt (wie E-Mail-Flow über `pathAfterAuth`)
- [ ] **Gleiche UID** wie Web-Login mit demselben Google-Konto (Firebase Console → Authentication → User)
- [ ] Optional: Haushalt anlegen oder PIN-Join — Firestore wie in Phase 1
- [ ] Negativ: In **Expo Go** bleibt Google ausgeblendet / Hinweistext — kein Regressionstest nötig, nur kurz bestätigen

## Typische Fehler

| Symptom | Erst prüfen |
| --- | --- |
| `DEVELOPER_ERROR` / Sign-In bricht ab | SHA-1 in Firebase, Android OAuth-Client, Paketname `com.familycompanion.app` |
| `Missing EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` | `.env.local`, App neu bauen (Env sitzt im Build) |
| Google-Button fehlt | Noch **Expo Go** — Dev-Build installieren (`Constants.appOwnership !== 'expo'`) |
| `Google Sign-In lieferte kein idToken` | Falsche Client-ID (Android statt **Web**-Client für `webClientId`) |
| Firestore `permission-denied` nach Login | Rules veröffentlicht (Phase 1), User hat Haushalt / Onboarding |
