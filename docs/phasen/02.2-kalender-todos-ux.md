## Ziel

Kalender und Todos von Hybrid-Minimal-UI zu **Cards + Modals** bringen; Kalender mit **Wochenansicht**. Gemeinsame Card-Sprache mit Heute (2.1). Keine neuen Features (Pro, KI).

## Entscheidungen (User-Test 2026-09-15)

| Thema | Entscheidung |
| --- | --- |
| Listen | Flache Zeilen → **EventCard / TodoCard** (Pills, Icons, Energie-Ampel) |
| Kalender-Ansicht | **Kalenderwoche** mit Vor/Zurück; kein Monat in 2.2 |
| Abhaken Kalender | **Nicht in der Liste** — nur im **View-Modal** (Daten für Phase 4 Kaizen/LLM) |
| Habits | **Kalender und Todos** — Kalender: zeitgebunden, für Haushalt sichtbar; Todos: Aufgabe/Habit ohne festen Slot |
| Habits nur Todos | **Zurückgenommen** — geteilte Kalendersicht wichtiger |
| Detail | **View-Modal** pro Eintrag (Infos ausführlich); Bearbeiten im selben Modal (Edit-Modus) |
| Add/Edit | **Modal**, keine Inline-Formulare; Chips statt Dropdowns (Web) |
| Neuer Eintrag | **Plus-Icon** — Web oben rechts in Card, Mobile FAB unten rechts |
| Zuweisung Anzeige | **Anzahl** Personen; **fett** wenn Actor dabei; Namen später |
| Zuweisung Formular | Phase 2 Stand (E-Mail-Checkbox) — Display-Namen später |
| Todos Abhaken | **Checkbox auf Card** ok (schnelles Abhaken); zusätzlich im View-Modal |
| Aktionen Liste | Keine großen Text-Buttons; Löschen `rust`, Bearbeiten neutral — im Modal |
| Jahres-Navigation | Termin-Counts an KW-Buttons — **später** (Performance) |

### Kalender vs. Todo (Nutzer-Logik)

| | Kalender | Todo |
| --- | --- | --- |
| Fokus | **Wann** (Slot in der KW) | **Was** (Aufgabe, Fälligkeit) |
| Habit-Beispiel | Fitness 18:00, wiederkehrend | Vitamine, Post — ohne feste Uhrzeit |
| Abhaken UI | Nur View-Modal | Card + Modal |
| Haushalt sieht | Termine und Kalender-Habits im Wochenplan | Offene Todos/Habits in der Liste |
